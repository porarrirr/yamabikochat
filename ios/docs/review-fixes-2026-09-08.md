| 指摘 | 変更 |

| R01 | 会話削除前に残存会話の添付・生成物参照を収集し、DB削除成功後に未参照ファイルだけを削除。生成物ディレクトリも参照中ファイルを保護。分岐と削除は共通ロックで直列化。単体・一括・プロジェクト削除に適用。 |
| R02 | 共有ペイロードIDを主キーにしたDB受信箱を追加。会話作成と下書き保存を同一トランザクションで実行。保存後に共有元をacknowledgeし、失敗時は取り込みループを停止。同じIDの再取り込みは冪等。下書きはユーザーメッセージ保存時に消費。 |
| R03 | 通常エクスポートに独立した許可項目方式のシリアライザーを追加。回答候補・Dual・自動会話の内部推論・ツールJSON・Pi JSONも出力対象外。診断モードは維持。 |
| R04 | 全PythonWorkerで共有するキャンセル可能な待機キューを追加。実行権取得後にウォッチドッグを開始。ネイティブ割り込みはGIL取得後に実行IDを確認し、別ジョブに適用しない。 |
| R05 | 深いシリアライズ前に累積message/messages/partialを除外。差分イベント記録を2 MiBに制限し、上限到達を診断ログ、成功スナップショットの欠落件数で明示。会話状態はイベント記録から独立して保持。 |
| R06 | HTTPレスポンスの異常close/errorでAgentをabort。キャンセル済みsignalでのツール待ち登録を防止。Swiftの一般エラーも独立タスク・5秒タイムアウトのabortで後始末。リスナー一時停止の既存テストは維持。 |
| R07 | 生成されたPi assistantオブジェクトをproviderTranscriptのpiMessageに保持し、Swiftの保存・要求変換を通してPi標準変換へ戻す。元モデル・API・署名を保持。旧履歴は由来不明として扱い、現在モデルの生成物とは偽らない。通常・Dualの最終回答重複を防止。 |
| R08 | PiRequestにskillContextを追加し、明示Skillの指示・リソース・対象メッセージ位置をJavaScriptへ渡す。 |
| R09 | 認証世代と同期ロックでログアウト・新規ログインによる無効化を実装。同じ資格情報の進行中解決は共有。古い完了結果の保存・トークン返却・デバイスコード反映を防止。 |
| R10 | 正常EOFに有効なcompletedを必須化。応答なし・重複completedはエラー。途中終了は保存側へエラーとして伝える。 |
| R11 | 信頼済みのdoctype/html/head/CSPを未信頼HTMLより前に構築。コメントや属性内の偽headを挿入先として探索しない。 |
| R12 | Fusionの対応添付を画像に限定し、PDF・テキストは取り込み・送信・要求生成で明示的に拒否。内容抽出や別API経路は追加していない。 |
| R13 | ProviderGatewayの同一モデル構成とPiモデル解決のinputを能力判定に使用。料金サービスから分離。未確認はエラーとして保持。Fusionの能力キーはprovider/modelの組で識別。 |
| R14 | 能力照会の世代と設定・provider・modelを結果反映前に照合。能力判定で既存下書き画像を取り除く処理を廃止。 |
