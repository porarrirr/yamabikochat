# テスト見直し — 2026-10-11

件数やカバレッジ率を増やすことより、「利用者が困る故障を検出できること」「仕様を変えずに実装を整理しても壊れにくいこと」を基準にした。iOS、Android、共通Pi Runtime、Python、ビルド用スクリプト、CIの構成を確認し、保存・中断・設定・検索の境界を重点的に見直した。

| 観点 | 見つかった問題と対応 |
| --- | --- |
| 重複・低い検出価値 | Androidのエラー消去・編集開始だけの2テストを、添付失敗後の復帰・編集送信のテストに統合。iOSの最新DBに列があるだけのテストを削除。データを保持するマイグレーションのテストは残した。 |
| テストの前提 | 「Secret Chat」という名前の通常会話を使っていたテストを、実際のシークレット会話に修正。想定外の例外でも通っていた検証を、認証情報不足の例外に限定した。 |
| 永続化 | 共有受信箱とストリーム復旧は、一時ファイルのSQLiteを閉じて開き直すテストに変更。別インスタンスを同じメモリDBに接続するだけでは確認できない保存を検証する。再生成した回答の復旧と、元の回答が保持されることも確認する。 |
| 中断 | 実行中タスクをキャンセルし、途中の回答・思考の保存、ツールの終了状態、チェックポイント削除、最終表示を検証。通常の回答と再生成した回答の両方を同じケースで確認する。 |
| 設定保存 | 認証情報の保存失敗時にDB設定とMCPトークンが戻り、入力を保持して再試行できるテストを追加。保存・再読込で同じ設定が別物にならないことも追加。 |
| 検索 | Androidで入力のdebounce、空欄に戻したときの結果消去、プロジェクト切替後に古い検索結果が割り込まないことを追加。ViewModelの後始末も行う。 |
| 不安定さ | 保存完了を900ms固定待機するテストを、状態の成立を待つ形に変更。会話の時系列テストはsleepで時刻差を作らず、明示した時刻を使用する。 |
| 外部依存 | 共通ChatRepositoryテストfixtureの料金取得を既存のスタブに変更。料金取得そのもののテストは専用fixtureで維持する。 |
| 古い仕様への依存 | ChatGPTの推論設定テストを、固定モデル一覧を前提とするものから、取得したアカウントカタログに従う検証へ変更。カタログ取得前・未対応の推論値も同じ流れで確認する。 |
| SDK内部への依存 | PCCはSDKの内部IDまで一致する疑似キャッシュ判定をやめ、セッション再利用、引き継いだ会話内容、SDKが報告した使用量を検証する。実際のキャッシュヒット率は実機の任意実行テストに任せる。 |
| 実行コスト・CI | App Store画像の一括撮影は明示実行に変更し、通常のUI動作テストは維持。Android単体テストのCIを追加し、既存のiOSスクリプトテスト5本をCIから実行する。 |

中断の追加テストで、キャンセルが正常終了扱いになりツールが実行中のまま保存される不具合を再現した。ストリーム消費中と終了時にキャンセルを確認する修正を行った。

設定の追加テストでは、JSONのキー順の変化によって設定の比較が不安定になることを再現した。設定内のプロバイダー別マップとFusionプリセットをキー順が一定のJSONで保存する。モデルの値や実行経路は変更していない。

プロバイダー解決、認証の競合、秘匿情報の保存・エクスポート、ツールの安全境界、Markdownやスクロールの既知の回帰テストは維持した。これらは一見細かくても、失敗したときの影響や過去の不具合に対応している。大きなテストファイルの機械的な分割、全getter/setterのテスト、表示文言や内部実装の網羅的な固定、新たな大量スナップショットは追加していない。

今後も、正常系と重要な失敗・境界を最も近い層で検証する。同じ振る舞いを各層で繰り返さず、パラメーターの違いは失敗理由を特定できる小さな表にまとめる。外部サービスへの実通信やスクリーンショットの生成は、通常の単体テストから分ける。DBの変更時は列名の確認だけで済ませず、旧データが読み出せることを確認する。

通常の確認コマンド:

```sh
./gradlew testDebugUnitTest
(cd ios/PiRuntime && npm test)
python3 -m unittest ios/PythonTests/test_yamabiko_runtime.py
for test_script in ios/scripts/test-*.sh; do "$test_script" || exit; done
cd ios
xcodebuild -project YamabikoChat.xcodeproj -scheme YamabikoChat \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro,OS=27.0' \
  -only-testing:YamabikoTests -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO test
```

UIを変更したときは該当する`YamabikoUITests`も実行する。App Store一括撮影を行う場合は、XcodeのTest用環境変数に`YAMABIKO_CAPTURE_SCREENSHOTS=1`を設定して`testCaptureAppStoreScreenshots`を実行する。PCC実通信の任意実行条件は`PCCProviderTests.swift`にある。

検証結果:

- iOS単体テスト: 778件、失敗0、スキップ4（PCC実通信3件と旧OS専用1件）。iOS 27.0のiPhone 17 Pro Simulatorで実行した。
- iOS UI: 設定画面の繰り返し遷移とプロジェクトソース操作の2件が成功。一括撮影の1件が通常実行ではスキップされることも確認した。
- Android単体テスト: 240件、失敗0。キャッシュ済み結果だけでなく実行して確認した。
- Pi Runtime: 72件、失敗0。
- Python: 8件、失敗0。
- iOSビルド用スクリプト: 5本すべて成功。
- CI定義: YAMLの構文を確認。GitHub上の新しいAndroidジョブ自体は未実行。

単体テストの純増はiOSの2件で、Androidは増減なし。全体の件数を膨らませずに、検出できる不具合を増やした。Androidの端末用テスト、実機・利用枠を必要とするPCC実通信、UIテスト全体の網羅実行は今回の検証には含めていない。
